## TL;DR

Iterative polish across the widget demos, scoped to:

1. **Hover & click states** — added a real hover state to suggested-messages chips (engine-driven, since the demo cursor doesn't trigger native `:hover`); fixed double-stroke artifacts on chips, form fields, and stripe buttons.
2. **Stripe drawer overlay timing** — blur stays solid through the drawer slide and snaps clear in the final 0.2s, instead of fading before the drawer settles.
3. **Layout & token polish** — chevron + heading inline in `PickerWidget` header, symmetric `metaGap={12}` around shopify widget cards, all primary buttons consolidated on `var(--bg-brand)`, `ChatCard` scale exposed as a `--card-scale` CSS variable (default `0.7`, matches dashboard widget size).

---

## Engine (`src/lib/`)

### `types.ts`
- `CursorWaypoint.hover?: TimeValue` — fade-in duration of the target's hover state as the cursor approaches. Implies `select`. No-op for elements without `[data-hover]` markup.

### `timeline-engine.ts`
- New `hoverData` aggregator. When a waypoint has both `select` and `hover`, emits two keyframes:
  - `hov-${id}` → applied to `[data-hover]` (opacity overlay)
  - `hov-text-${id}` → applied to `[data-hover-text]` (color tween between CSS vars `--hover-text-idle` and `--hover-text-peak`)
  - Fades in over `hover` ms ending at cursor arrival; crossfades out across the click as `select` takes over.
- `selectionData` emit now also produces a mirror `sel-inv-${id}` keyframe (opacity inverted), and applies `sel-${id}` to `[data-label-selected]`, `sel-inv-${id}` to `[data-label-default]`. Enables paired-label crossfades like "Select → Selected" without engine knowledge of the labels themselves.

## Suggested-messages (`/demos/suggested-messages`)

### `SuggestionChips.{tsx,module.css}`
- Added `<span data-hover>` overlay (`#fafafa` bg) and `data-hover-text` on the label.
- Defined `--hover-text-idle: var(--text-heading)` and `--hover-text-peak: #3f3f46` on `.chip`, per Figma `802:10802`.
- `position: relative` on `.icon` and `.label` so they paint above the absolutely-positioned hover overlay in DOM order.
- Click ring switched from `inset 0 0 0 2px` → outset `0 0 0 1.5px var(--text-heading)`. The 1.5px black paints **over** the chip's existing 1px gray border, eliminating the double-stroke artifact. Matches Figma `802:11303`.

### `timeline.ts`
- `chip-plans` waypoint: added `hover: '0.3s'`. Hover crossfades in over the cursor's last leg of travel.
- chips-2 fade-out: `pause: '3s' → '5.84s'`, `duration: '0.5s' → '0.9s'` so the transition lands inside the messagesStack outroFade window — chips and messages now finish fading at the same beat.

## Forms (`/demos/forms`)

### `FormInputRow.module.css` + `FormTextareaRow.module.css`
- Replaced `border: 1px solid var(--border-subtle)` with `box-shadow: inset 0 0 0 1px var(--border-subtle)`. The 2px black focus ring (also inset) now paints from the same edge and fully covers the gray. Single visible stroke when focused.
- Required because `.field` has `overflow: hidden`, which would clip an outset shadow.

### `CTAButton.{tsx,module.css}`
- Removed `[data-ring]` overlay span entirely. The white-40% inset shadow on the dark-button bg read as light gray on click. Click anticipation is preserved through the engine's `pulseData` (transform: scale).
- `.ring` CSS rule deleted.

## Stripe (`/demos/stripe`)

### Dark buttons — Update plan + 3× Confirm
Removed `[data-ring]` from `SubscriptionsCard`, `PlanPickerCard` (Confirm), `BillSummaryCard`, `PaymentMethodsSheet`. Same rationale as `CTAButton` — the white-60% inset on dark bg read as light gray. Pulse-scale still drives click anticipation.

### Select button (`PlanPickerCard.selectBtn`)
- Ring switched to outset `0 0 0 2px var(--text-heading)` so the dark stroke covers the 1px gray border (single stroke).
- New markup pattern:
  ```tsx
  <button id={p.selectId} type="button" className={styles.selectBtn}>
    <span data-label-default className={styles.selectLabel}>Select</span>
    <span data-label-selected className={`${styles.selectLabel} ${styles.selectLabelSelected}`}>Selected</span>
    <span data-ring className={styles.selectRing} aria-hidden="true" />
  </button>
  ```
- Engine drives the label crossfade automatically via `sel-${id}` / `sel-inv-${id}`.
- `display: inline-grid; grid-template-columns: auto;` on `.selectBtn` so both labels share an auto-sized cell — button width = max(label) + 16px L/R padding. `Selected` (the wider label) determines the size.

### Brand color tokenization
All `.btnPrimary` / confirm buttons now reference `var(--bg-brand)` (= `#09090b` from `globals.css`). Touched: `SubscriptionsCard`, `BillSummaryCard`, `PlanPickerCard`, `PaymentMethodsSheet`. Radio-dot/border literals at `PaymentMethodsSheet.module.css:71,78` left alone (not buttons).

### PaymentMethodsSheet overlay timing (`stripe/timeline.ts`)
- `meta` step `sheet-overlay` lifecycle: `fadeIn: '0.4s', hold: '1.0s' → '1.6s', fadeOut: '0.4s' → '0.2s'`.
- Iteration history (for context):
  - **Original:** blur disappeared before the drawer finished its 0.7s slide (visually unsynced).
  - **First fix attempt:** `hold: '1.8s'` made the fadeOut start *after* the drawer slide, but felt too slow.
  - **Second iteration:** `hold: '1.4s'` aligned end times but was still too long.
  - **Final:** `hold: '1.6s', fadeOut: '0.2s'`. Blur stays solid through the first ~71% of the drawer's 0.7s slide and snaps clear in the final 0.2s. Both end at the same beat.

## ChatCard (`src/components/ChatCard/`)

- Replaced hardcoded `transform: scale(0.7)` with a `--card-scale` CSS variable on `.scaledWrap` (default `0.7`, same as before).
- Wrapper width/height computed via `calc(406px * var(--card-scale))` etc., so layout footprint follows the visual size.
- Override on a parent (e.g., the dashboard preview slot) to render at a different size:
  ```tsx
  <div style={{ '--card-scale': 1 }}>
    <ChatCard>...</ChatCard>
  </div>
  ```
